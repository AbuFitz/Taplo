# Taplo design review

Use the current user request to determine whether this is preparation, implementation or review. This skill does not authorize starting implementation, spending another agent's usage, deploying or changing customer data. In preparation mode produce artifacts only.

Read repository instructions and the current branch before working. The founder has rejected repeated superficial refinements. Establish the current deployed version separately from repository HEAD, and classify inherited findings as still present, resolved, regressed or unverified.

For evidence and the known baseline read `../../../docs/taplo-rebuild/AUDIT.md`. For implementation invariants and task flows read `../../../docs/taplo-rebuild/ENGINE-AND-UX.md`. For art direction, source content and campaign scenes read `../../../docs/taplo-rebuild/CREATIVE-BRIEF.md`. For tooling decisions read `../../../docs/taplo-rebuild/TOOLING.md` only when needed.

Read `../../../docs/taplo-rebuild/ENGINE-REVIEW-MATRIX.md` and `../../../docs/taplo-rebuild/CUSTOMER-JOURNEY-AUDIT.md` for whole-system contracts and current journey defects.

Choose real populated content and render through the shared Taplo renderer. Differentiate visual look, composition, industry suggestions and business records. Theme application must preserve the owner's information; demo seeding is a separate isolated operation.

Compare a small number of materially different directions on the same hero, editor and customer-page state. Evaluate hierarchy, image relevance, type, primary action, mobile information density and coherent detail/booking overlays. Palette swaps and newly captured old screens are not distinct art directions. Retain a successful incoming design when it meets the brief.

Build the accepted pattern through one owner-to-customer journey before spreading it across the catalogue. Cover the whole registry and routes after the pattern is proven. Do not treat finishing one example as completing the overall scope.

Use the existing component workbench and real UI captures. Add tools only to close an evidenced gap. An installed package, written spec, passing build or screenshot count does not establish visual quality.

For each requirement record artifact/screen, viewport, state, result, remaining limitation and current version. Use `../../../docs/taplo-rebuild/ACCEPTANCE.csv` as the review ledger. A missing real device or provider remains unverified; a demo success is never described as production confirmation.

Report what changed visually and behaviorally, what was actually tested, and what remains. Preserve open items instead of marking a whole stage complete because some tasks in it were done. Honor any explicit owner request to stop at a review package before further rollout.
