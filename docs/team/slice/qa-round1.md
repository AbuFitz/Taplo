## Defects found (beyond the criteria wording)

A. Mobile dock is not pinned at default motion. `.studio-dock` is `position:fixed; bottom:max(14px,...)` at <=760px, but the shell animates `.portal-workspace[data-workspace-section="manage"] main>div{animation:portal-arrive 220ms ease-out both}` whose end keyframe has `translate:0 0`. With fill-mode `both` that stays applied, so `.studio` becomes the containing block for the fixed dock. Observed: 390x844 published, dock y1214-1274 (viewport 844), it scrolls with the page and sits at the end; injecting `*{animation:none !important}` or enabling reduced motion puts it at y770. Reproduced 3 times (dock.js, dock3.js, dock5.js). Effect: on a phone the dock (and Share shortcut) is below the fold; with reduced motion it floats. Read before calling: studio.css lines 68-69 and portal-workspace.css lines 33 and 37.
B. Primary filled buttons have no visible focus indicator (see 12b).
C. Three different addresses for one page (see 9 and 10); the displayed one (`mytaplo.com/...`) is not what Copy copies or what the QR encodes. Contract truthfulness question for the owner, not just copy.
D. Spec section 2/9 preview scale: frame is 523px at 844 (62%) and 340px at 600 (57%); spec says about 46% and max 40%. Numbered criteria 1 and 2 still pass; flagged as a deviation only.
E. Section 9 error string: spec "Select the link and copy it", build "Select the address and copy it".

## Limitations
- Chromium desktop emulation at 390x844, 390x600, 1440x900. Not a real phone, no touch hardware, no iOS Safari, no software keyboard or `visualViewport` (criterion 16 not testable).
- Clipboard denial was simulated by replacing `navigator.clipboard.writeText` with a rejecting stub, not by a browser permission prompt. Success path used granted permissions and read the clipboard back.
- State seeded via localStorage JSON; bookings/enquiries seeded directly in the booking store. Preview failure by request abort. No real accounts, payments or messages. No participants or user testing; nothing here is user evidence.
- Existing Playwright suites and unit tests were not run in this pass (not requested); no baseline versus regression comparison was made.
- Loading state observed only with CPU throttle plus the cached bundle; slower networks might expose it longer but cannot change which component renders.
