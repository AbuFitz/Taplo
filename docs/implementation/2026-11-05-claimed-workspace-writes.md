# P03: versioned claimed workspace writing

Once an onboarding draft is claimed, an authenticated merchant with an active owner or manager membership can read the private authoring document and save a later version through `GET`/`PUT /v1/businesses/{business_id}/workspace`. `PUT` requires a same-origin request, an exact quoted `If-Match` version, an idempotency key and the validated complete workspace envelope. Only the current version may advance. The write, command receipt, audit event and outbox event commit together; retries of the same operation rehydrate the current same-version document, while an old receipt cannot return stale content over another edit. The receipt omits private page/image content. A per-actor rate window bounds writes; a malformed/oversized document is rejected before mutation.

Migration 0006 adds an update policy constrained by tenant context and active owner/manager membership and grants only `snapshot`, `version` and `updated_at` column updates to the runtime role. The service checks current business state, membership and merchant audience before a receipt is accepted. Closed/closing businesses, revoked/foreign members, customers and practitioners cannot use the command. Ordinary users receive no direct browser database permission. The authored document remains private: saving it does not publish a page, create an offer, change inventory, settle payment, alter entitlement or assert a completed setup.

This is a backend command and contract slice. The current Studio still uses its review store; there is no authenticated business picker, signed-in draft claim handoff or ongoing client synchronization yet. The Studio footer must not present a server save as confirmed until that connected path exists. The production/provider configuration is unchanged. Install migration 0006 in an isolated target and verify the principal and tenant roles before enabling this API for real owners. Authenticated setup recovery, image assets, clean merchant exit and operational record mapping remain separate tracked work.

Verification: the isolated PostgreSQL suite exercises concurrent same-key writes, atomic event/receipt count, full document return, stale replay, foreign actor, customer audience, practitioner role, manager permission, revoked membership, closing business and update-column grants. HTTP tests check origin, If-Match and no-store/ETag response. Local TypeScript, lint and build gates and CI are recorded separately when complete.
