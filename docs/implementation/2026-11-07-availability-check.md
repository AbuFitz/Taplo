# Studio availability check · 7 November 2026

P03/P04, Studio Bookings → Availability. An owner can select a bookable service, eligible team member and date. The checker evaluates the existing slot engine using the workspace's current rules, appointments and unexpired holds. It reports the candidate times or the constraints that eliminated them. Its team selection respects the customer-facing plan limits and its dates use the public calendar's current query horizon. It is read-only. The customer booking picker now derives its next date from the same hold-aware result as the slot grid. Team profile availability also accounts for holds.

The reference for making availability explainable was [Cal.diy's troubleshooter](https://github.com/calcom/cal.diy/blob/2eb48eccd8aca8a0c0ffabf28cf92e298b33ecee/apps/web/modules/troubleshooter/components/Troubleshooter.tsx), read alongside [its availability service](https://github.com/calcom/cal.diy/blob/2eb48eccd8aca8a0c0ffabf28cf92e298b33ecee/packages/features/availability/lib/getUserAvailability.ts). [Easy!Appointments' availability library](https://github.com/alextselegidis/easyappointments/blob/f6c8a4c2f364bf8c64b1f913a531a7134dcfd3c6/application/libraries/Availability.php) shows how working periods, unavailability, multi-attendee rules and lead time compose. Taplo already has those scheduling primitives. The change adds explanation to its existing engine without importing third-party code or dependencies. [FullCalendar's time grid](https://github.com/fullcalendar/fullcalendar/blob/31a0d960920abbe0436e65c8cb0a4cc9a661438f/packages/preact/src/timegrid/components/TimeGridView.tsx) was checked as a renderer reference. No replacement calendar component was needed for this feature.

This slice uses the existing scheduling adapter. No schema, transaction, payment or provider changes. Server-backed public scheduling, real provider busy time, multi-seat holds and resources such as rooms or vehicles remain separate work.
