# Three directions, one decision

`a.html`, `b.html`, `c.html` (rendered as `a.png`, `b.png`, `c.png`) compose the same populated homepage hero and the same editor screen three ways, from real captures of the product. The editor screens use the real editor capture; direction A's dark chrome is a recolour for comparison, not a built theme.

| | Hero | Editor | Verdict |
| --- | --- | --- | --- |
| A, studio dark | One huge phone on near-black, a second behind it, 112 px type, cobalt button | Dark chrome | The most confident and the most mobile-led, but a dark workspace makes customer colours harder to judge: a dark Night page and a pale Clean page are both judged against black |
| B, product light | Three phones side by side, white page | Light, panel beside preview | What the site already was: clear but evenly weighted, no focal point |
| C, calm cool grey | A single phone rising from the bottom edge, centred headline | Light, preview given a raised stage | The best focal point and pacing; centred type is less useful beside a left-hand editor |

**Chosen:** A's scale and single-phone confidence, C's rising crop and neutral stage, B's light workspace. In practice: a light cool-neutral platform, a left-aligned headline, one large phone with a smaller second behind it fading at the bottom, cobalt as the only accent, 8 to 12 px radii.

Principles applied: Linktree's one obvious next action and choose-before-configure; Framer's large tight type, compact navigation and one product image per idea; Apple's single hero object, generous space and an image that does the explaining. These are taken as principles from the public sites and documentation, not as layouts or branding. The sites were not browsed during this work, so no specific observations of them are claimed.
