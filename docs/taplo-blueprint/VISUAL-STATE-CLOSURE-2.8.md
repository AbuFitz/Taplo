# Taplo · Visual state production and closure

Working edition 2.8 · 3 November 2026. contracts/visual-screen-closure-register.json specifies the important onboarding/Studio/customer/Console screen families and required compositions/states. This is a production inventory; it does not claim all screens are final. LOW-FRICTION-REFERENCE.html supplies four selected authored interactive compositions with fictional records. They are reference design work, not live product integration.

## Common component recipes

Operational type: Inter fallback sans; 16px normal text with 1.45–1.6 line height, 14px secondary only where legible, major headings 28–40px responsive, 12px labels only non-essential context. Actual licensed bundled fonts and exact optical review remain required. Layout spacing 4/8/12/16/24/32/48; primary controls at least 44px touch target; focus 2px distinct ring with offset; 1px dividers are separators rather than boxes around every section.

Frameless means aligned typography/space and one calm task canvas. Avoid a dashboard of rounded cards around every datum. White/near-black operational surfaces; brand accents highlight action or selected state. Merchant popup content stays neutral/contrasted, with Clear/Colour cap/Split tone appearance families under shared legibility rules. Sheet radius 24–28px mobile top corners, 20–24px desktop modal; no owner control defeating contrast or moving primary/close semantics. Logos preserve transparent assets/contain geometry; no forced circular outline or invented name initials.

State components: labelled skeleton preserving geometry; field error attached with described recovery; busy button plus durable operation state; non-blocking completion with persistent activity receipt; conflict review preserving entered values; offline draft retained; unknown financial result uses Check status. Explicit close/back with accessible label, trapped/restored focus for actual modal, Escape and dirty-draft handling. No interaction depends only on hover, swipe, hue or a disappearing toast.

## Device composition

390px: page padding 20px, primary task full readable width, essential action clears safe area and keyboard; horizontal showcases reveal continuation without requiring page-wide scroll. Onboarding draft not trapped in a tiny fake phone. Merchant page title/logo does not repeat in every block. Studio task opens in current context; short related editor uses one focused sheet. Console prioritises case next action/timeline before wide evidence tables, which scroll within labelled regions.

768px: switch by readability and task, not an arbitrary desktop-sidebar assumption; single task plus optional preview, no narrow centre column between multiple side panels. 1440px: max readable task width, optional real preview/context, nav does not frame every page. Map uses one results rail rather than a second duplicate card; attribution stays visible. Reduced motion removes travel/scale and unnecessary autoplay. Focus/scroll/draft are stable on theme/category/editor changes.

## Screen-level required artefacts

Each screen ID needs exact content/source fields, actor/permissions, mobile/tablet/desktop frame, light/dark, empty/loading/error/denied/conflict/unknown states where applicable, copy, keyboard/focus/touch rules, variable content extremes, source-token/component references, motion/reduced-motion and annotated task transition. Mark inapplicable states with reason; no fake pass across a huge cartesian matrix. Provider checkout, Wallet and OS permission surfaces use their actual APIs/approved appearance instead of invented replicas.

Four new scenes illustrate recognisable draft; service with in-context weekly hours; clear deposit review; Console unknown-refund recovery. Their local controls are illustrative and don't produce real backend/payment/provider changes. Actual working-hours validator is separately tested at the proposed contract boundary. Full final designs across the register still require construction/review; no final-design badge is assigned by this document.
