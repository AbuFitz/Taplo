## Tool choices serve outputs

Do not expect an instruction such as make it premium to produce a complete experience. Each agent task needs the exact workflow, reference composition, tokens, state/copy contract and evidence required by 94. Tools help produce and inspect those artefacts; they do not decide merchant responsibility, consumer rights or what a booking means.

| Need | Working default | Output and boundary |
| --- | --- | --- |

| Accessible interactions | Radix primitives where appropriate, styled with Taplo components | Dialog/popover/select behaviour plus separately reviewed composition, labels and focus |

Radix documents support for ARIA patterns/focus/keyboard; Motion documents reduced-motion controls; Storybook supports component accessibility checks; Playwright provides retrying assertions. These capabilities inform the defaults, not an assertion that adopting them automatically makes Taplo accessible, beautiful or bug-free. [R65–R68]

Exact package versions must be selected against the actual repository and current compatibility/security/licence evidence at implementation time, then pinned. This blueprint does not invent version numbers or require a wholesale dependency upgrade. Existing use of Lucide or other assets needs a deliberate migration plan if replacing it with the chosen family.

## Capability modules for Codex, Claude or other agents

These are required workflow capabilities, not claims of installed skills or independently running specialists. Bundle them into actual agent instructions/skills only through the relevant platform's supported mechanism and verify they are available.

1. **Requirement resolver:** reads current decision/spec/contracts; returns intended behaviour, conflicts, defaults and source trace.
2. **Interaction/composition designer:** specifies full journey and mobile/desktop/light/dark/material states, using Taplo grammar and real content.
3. **Visual craft reviewer:** critiques density, hierarchy, typography, asset quality, logo/name use and branded restraint against actual captures.
4. **Motion/media author:** chooses still versus interaction versus video, writes timing/interaction/reduced-motion contract, produces source and exports.
5. **Frontend implementer:** builds shared components and accessible stateful flows without inventing domain policy.
6. **Domain/integration implementer:** enforces permissions, idempotency, time/stock/money and provider recovery.
7. **Security/privacy reviewer:** checks tenant/field boundaries, tokens, uploads, logs, consent and retention against supported scope.
8. **Verification/release reviewer:** selects meaningful critical scenarios, captures evidence, identifies limitations and dependency regressions.

These roles may be sequential in one agent. No delegation, installed tool or background work is implied. Tasks are not ready merely because eight role names exist; each needs inputs, output criteria and a demonstrable result.

## Motion contract

Working token ranges: fast feedback 100–160ms, surface transition 160–240ms, deliberate contextual transition 220–320ms. These are design defaults to tune against real devices, not accessibility thresholds. Use restrained ease-out; avoid playful spring/bounce on financial decisions and required setup. Animate opacity/transform when appropriate; do not move an active input away from its focus/keyboard or shift the payment CTA under a finger.

Specify trigger, start/end state, interruption/reversal, focus timing, reduced-motion equivalent and loading/failure behaviour. Readiness never waits for a decorative animation. Repeated actions cannot initiate duplicate mutations while a transition plays. Preserve task state on resize, route change and reduced-motion preference changes.

## Help-media production contract

Every asset has a task/purpose, related UI/spec version, synthetic-data fixture, source project, transcript/captions as appropriate, still fallback, dimensions/duration, playback policy, rights/provenance, file-size budget and expiry/review trigger. Capture or recreate the actual supported UI, never a beautiful impossible interaction. A changed UI invalidates affected instructions for review.

For short clips, select the authoring/render pipeline when the specific media task is assigned; reuse the environment's available video/motion workflow where suitable and verify its output. Do not make a particular ChatGPT-only skill a production runtime dependency. Product motion runs in the app; a video renderer produces optional media assets. Native/browser fallback, poster and text must work without that renderer.

## Build/review loop

Resolve feature packet → design populated state set → produce shared components/contracts → integrate a connected task → inspect actual browser result → run appropriate checks → correct material failures → record evidence. Do not leave visual inspection until the entire product is built. Conversely, do not spend an unbounded budget recapturing an unchanged low-risk label once relevant checks have passed.

Definition of a good delivery: the first-time owner can complete the relevant setup, a customer can perform/manage the task, staff can operate it within permissions and Console can diagnose its defined failures. Required deliverables include code/assets, changed decisions/contracts, meaningful validation and unresolved risks. Broad claims such as looks premium or all tests green are insufficient on their own.
