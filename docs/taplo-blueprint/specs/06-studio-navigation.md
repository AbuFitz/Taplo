# Studio: organise around work

Status: proposed information architecture. Depends on: 10, 27.

Recommend Today, Offers, Activity, Customers and Page as stable main concepts. Calendar appears as a primary working view for businesses using scheduling. Money and Settings are supporting destinations. Owners can pin relevant work views, but must not build their own navigation from scratch.

Offers contains products, services, sessions, packages and quoted offers with type-aware editors. Activity contains work generated by customers: orders, appointments, enquiries and quotes. A calendar is a view of scheduled activity, not a second source of booking truth. Customers presents authorised relationships and their related history.

Today is an actionable queue: upcoming work, orders needing preparation, requests awaiting a decision, failed customer messages and support deadlines. Each row names the customer/task, reason it needs attention, deadline and next action. Do not make a new owner confront empty revenue graphs before they can add an offer.

Navigation adapts to capabilities, not cosmetic category labels. A barber selling products sees fulfilment tools; a maker running workshops sees sessions and attendees. Hidden capabilities remain discoverable through “Add another way to sell”, not inaccessible.

Acceptance: the same owner creates a product, fulfils an order, edits the page and reviews an appointment without duplicated settings. A customer-service staff member can handle enquiries without seeing payout controls. A mobile owner can finish the day's next task without exploring Settings. Search and direct links open the same editor and preserve business context.
