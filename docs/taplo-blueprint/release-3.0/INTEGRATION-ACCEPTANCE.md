# Integration acceptance and actual evidence

Build all adapters against these contracts with synthetic fixtures. Actual account/provider/device/legal/user evidence is a separate release gate and must not be faked. Use the existing 22-case Wallet/native pack, 28-control compliance register and observation pack alongside this canonical handoff.

| Adapter | Selected contract | Actual acceptance |
| --- | --- | --- |
| Stripe | Direct merchant charges, separate SaaS billing, hosted/embedded onboarding, server amount/idempotency, account-scoped webhook signature/inbox/reconcile | Real supported account/controller/loss config in test mode; can-charge vs can-payout; duplicate/out-of-order callbacks, decline/3DS/timeout/late capture, partial/full refund and dispute visibility; before real money, actual provider agreement |
| Google Calendar | Free/busy input by explicit chosen resources/calendars; least scope calendar.events.freebusy where supported; separate deliberate event-write consent | Verify current scopes/account API, revoke/refresh, private label, recurrence/DST, freshness and duplicates. Read scopes alone don't export events |
| Microsoft Graph | Delegated getSchedule current least-privilege Calendars.ReadBasic where supported; event export requests relevant write scope separately | Current API reference differs from older overview; pin v1.0/account support and test actual grant, refresh/revoke/private busy; no tenant-wide application permission as default |
| Better Auth/Apple/Google/email | Server identity + separate Membership; all-method assurance gates, protected recovery/linking, Apple relay | Actual pinned library and OAuth clients/audiences; no provider-email auto-merge; staff mismatch; social/passwordless MFA gate; expired/duplicate code/session/CSRF/audience/guest claim tests |
| Resend/Twilio | Purpose-specific durable logical sends, suppression at dispatch, bounded segment/recipient quota, protected source facts | Actual sender/stream/account permission and DPA; real email client template render; deliverability/events unknown outcome; Unicode/multipart and opt-out; retries no duplicate billing |
| Mapbox | Own merchant index, GL JS/native SDK custom style, attribution/privacy/location query licence separate | Actual SDK wrapper/version billing, restricted tokens, coordinate licence, denial/cluster/list/back/slow tile, measured load invoice; style reference alone not live map |
| Apple/Google Wallet | Signed Apple pass/registrations/APNs; Google issuer class/object/publishing; public card vs loyalty | Real signed test passes and phone scans; Apple pass update supported production APNs with isolated tests; Google demo doesn't prove publishing; certificate rotation/offboarding, real display lag |
| Expo/stores/widgets | Two native apps, deep links, secure sessions, redacted cached widgets | Actual supported devices/OS, staged store builds, privacy/deletion/disclosures, native SKU/payment eligibility, large text/permissions/keyboard; no generic WebView workaround for digital purchases |
| Domains/NFC | Connect domain first, ownership and DNS/certificate verified; NFC stable public URL | Preserve MX; stale/expired/transfer/offboarding; actual mobile tag compatibility/hardware obligations later. QR camera scanning needs no NFC terminal |
| Backup/recovery | Scoped encrypted backups and provider history, explicit RPO/RTO target then measured | Isolated full restore, replay control, payment/message/reward reconciliation and deletion/suppression reapplication; static SQL parse not restore proof |

Evidence record: actor/owner, version/build/API, mode, actual account scope, synthetic fixture, expected/observed result, safe trace, defect, retest and approval/date. Default specified or blocked_prerequisite. Library/helper/API keys never in repo, fixture images, analytics or agent prompt. Provider account credentials are actual inputs, not missing creative decisions Codex should invent.

Working operational targets to validate: API error/latency and queue age alarms by critical action; candidate availability source freshness; backup age/restore time; email suppression and quota correctness; duplicate/concurrency counts; support repeat causes. Exact numerical production SLOs depend on real load/recovery rehearsal; don't promise a contractual SLA from a spec. Pause affected risky capability and retain accepted-work recovery if a provider is unavailable.
