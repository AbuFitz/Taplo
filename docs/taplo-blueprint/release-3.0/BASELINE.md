# Taplo 3.0 · Build baseline and closure boundary

This edition consolidates a build specification across the six requested workstreams. It adds populated reference compositions for all 67 registered screen families, canonical typed command/record/permission/event contracts and storage draft, thirteen category operating profiles/configurations, twelve connected journeys, operating/provider/retention/legal-input schedules, commercial/acquisition programme and ordered Codex handoff. History stays preserved; this folder is the new entry point.

## Product direction

Compact business mini-spaces with typed blocks, horizontal product rails and readable rounded popups. One identity across direct links, NFC/QR, existing websites, Explore and Saved. A private return view gives appointments/orders/actions/rewards without making discovery compulsory. Studio is task-first/capability-adapted, not a registration form asking every future question. Console is separate workforce authority. Light/dark/system, brand-safe contrast, no invented initials/repetitive logos. Team logins/profile/resource/seller relationships distinct, no per-member fee. Native commerce is Taplo's, with controlled website companionship and explicit exclusions.

## What is and is not closed

The authored baseline supplies decisions, field/action/state definitions, reference layouts and implementation sequence for the stated scope. Static validation can check consistency and local reference rendering. It does not transform reference HTML into implemented product, generate every production-quality pixel/animation/native/provider screen, prove all transactions secure or manufacture actual company/legal/vendor/customer evidence. Significant engineering/design judgement and actual runtime testing remain part of building; Codex must follow the stated contracts and surface conflicts instead of inventing facts. No “brainless build” or numeric correctness guarantee is claimed.

Actual external inputs are tracked, not disguised as missing product ideas: company/supply/region/account credentials and agreements, professional approvals, actual provider/device/security/restore results, observed customer/commercial evidence. Implement against synthetic fixtures now; enable affected production capabilities only with actual evidence. Entity/retention/provider drafts remain blocked for publication where facts/review are missing.
