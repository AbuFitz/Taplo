# Taplo 3.0 · Engineering contract

Canonical shape/API/action/event files in contracts supersede conflicting older proposed shapes. Historical research remains source material. The specification is not an implemented or tested server. Use schema, policy, transaction rules and acceptance fixtures together.

## Request, authority and recovery

Resolve current identity/session and business membership; apply action + location/resource/assignment + field projection + state + assurance, then separately plan/capability readiness. All reads, exports, file links, background jobs and subscriptions obey the same authority. A valid ID or paid plan does not grant a field. Public report and scoped unsubscribe routes don't require account login; rate/abuse protection and token verification remain. Verified guest-management tokens are purpose-bound credentials, not public share links.

Write idempotency scope: business + principal + command + key. Store payload hash before external calls. Same key/hash retrieves current/final response; changed hash returns 409 IDEMPOTENCY_CONFLICT. Retain command receipts 90 days for operational retry, with financial source/transaction reference retained under the reviewed financial schedule; after receipt expiry never repeat money merely because a key is absent. Existing aggregate mutations require If-Match and matching body version. Wrong tenant returns non-enumerating 404; current scope denial 403. Validate JSON/formats, then semantic rules; malformed input 400, valid shape/unmet rule 422, stale version/availability 409, rate 429, definite precommit outage 503. Unknown provider result is 202 plus stable operation ID/status route. Do not tell the client to pay/refund again.

200 carries the operation's exact documented response projection; 202 carries ProviderOperation. Safe errors carry code, message_key, field_errors, request_id, retryable and optional operation_id. Current_version may be returned only inside allowed projection. HTTP cache never stores authenticated private responses publicly. Browser sessions use appropriate host-only secure cookies/CSRF; bearer scheme in the API contract describes native/first-party credential authority, not a requirement to put browser tokens into localStorage.

## Money, time and stock

All prices/quotes/policy come from server records, integer GBP minor units; no client amount authority. Deposit-fixed cannot exceed remaining eligible total; deposit-percent rounds half-up once on the agreed line/base; no-upfront has zero charge; full captures remaining agreed amount. Money state is separate from booking/order/refund/fulfilment. DepositAllocation totals reconcile to captured/refunded/application amount. Sum successful/pending reserved refunds cannot exceed captured less earlier successful/active refunds. Full/partial refund policy is assessed before a durable refund intent; processing fees and Taplo application fees have distinct reconciliation. Launch application fee is zero. Automatic future card-on-file/no-show charging is disabled in this baseline; add only with a separate reviewed mandate/authority packet.

Reservation holds expire after ten minutes by default, server UTC; quote expiry is separate. Lock all constrained resource/variant/session rows in stable ID order in a DB transaction, re-evaluate current stock/capacity/time/price, then write hold and audit/outbox. A bag alone doesn't reserve stock. Never hold a DB transaction over network/provider calls. At commit re-lock/revalidate unexpired hold and exact agreement/payment readiness. Payment arriving after expiry rechecks capacity: safely confirm only if still valid, otherwise create defined refund/recovery case. Never sell a second seat/unit because a callback was late.

Resources use actual occupied intervals and quantities; bookings intersect working pattern/exceptions/busy/calendar-freshness/travel/offer eligibility. Lock resource calendar/revision while making allocations; range overlaps consume capacity, not merely duplicate starts. Classes count participant seats, not payers. Recurring commitments materialise dated occurrences with IANA timezone/local intent; DST non-existent times require owner/customer correction, ambiguous folds show explicit offset/occurrence. Changing one occurrence never silently changes the series. Mobile travel uses explicit conservative buffers/coverage, not an unbuilt route optimiser. Reschedule reserves new constraints before releasing old within the same authoritative transaction.

Stock distinguishes sellable, held, committed, unavailable and received-return disposition. Refund isn't restock. Partial fulfilment/refund uses line quantity/allocated amount; mixed merchant carts are not allowed. Mixed product + class work has one merchant but separately constrained components and explicit fulfilment/time; if the selected composite checkout isn't implemented, reject before taking money, retain both drafts and offer separate clear flows. Tax/fees/fulfilment totals and seller are shown before commitment, with immutable agreement snapshots.

## Marketing, guidance, rewards and Wallet

ConsentEvidence uses sender_scope/recipient/channel/purpose/basis/notice/time/evidence; Suppression is separate and overrides dispatch. Migration from the old models quarantines missing or ambiguous evidence. Operational intent never inherits marketing permission; immutable operational facts/required text cannot be edited into promotions. Campaign preview/approval binds current revision/template/audience/caps, expires after five minutes; edits invalidate approval. Reserve campaign quota once, settle on provider acceptance, release only definite preacceptance rejection; bounce is not a free send. Unsubscribe before dispatch suppresses that recipient even after audience snapshot. Already accepted sends cannot be recalled. One SMS balance is segments with honest Unicode/length audience preview and no default auto-top-up.

Guidance completion derives from current canonical source revisions. Dismissal isn't setup. Quick/full editors use identical mutation/validation; preserve hidden advanced fields and originating task draft. Working-hours v2 exact impact protocol remains normative; no free-form legacy parsing shortcut.

Rewards append entries; balance is derived under concurrency controls. Eligible paid/completed/attended source can earn once per programme/relationship/origin across rule revisions; receipt/manual cash provenance truthful. For launch every redemption uses a fresh single-use holder challenge from the customer's protected return view, bound to programme/source, five-minute expiry, plus current authorised staff action. This selects a concrete anti-screenshot policy instead of an undefined high-value threshold. A static pass resolves context only. Atomic challenge consume + entitlement reserve/debit + audit; no offline debit. Refund reversals append once per refund/correction origin, with cumulative reversal bounded by original eligible earn; already redeemed value creates reviewed recovery case, never a secret new customer charge or edited historic ledger.

Wallet purpose separates public business_card from private loyalty, with distinct holder fields and code namespace. Apple signed-pass/APNs registration and Google class/object issuance/update stay server-side; issuer signing material only in secret manager. Credential references aren't raw keys. A clicked Add badge isn't installation proof; distinguish issued/provider accepted/observed registration. Offline pass display may lag or survive revocation; authority lives in current server record. Public card never authenticates staff or spends rewards. Team departure resolves public links and revokes access, no redirect to unrelated new employer. Widgets are redacted snapshots with stale expiry and reauthorised deep links, not live stock/payment authority.

## Provider and state machines

Outbox/inbox have at-least-once behaviour; dedupe provider account+event ID, verify actual signatures/timestamp/replay limits before mutation, and re-read provider truth when needed. Source aggregate version prevents stale projection regression. Backoff bounded exponential retries with jitter and a durable next attempt; permanent error/unknown outcome enters reconcile/case, not infinite blind retries. Side effects audit their source intent/subject/version and respect current policy. Workers don't need a departed creator to keep necessary accepted-work receipts flowing, but cannot acquire new discretionary staff powers.

Auth provider IDs/audiences/relay/scopes and MFA gate are pinned in implementation; the current library's social/passwordless paths need explicit assurance verification. All-method server assurance tests precede sensitive access. Fresh step-up default five minutes for financial policy, broad exports, ownership, bank changes and privileged Console actions. Never auto-merge by matching provider email. APIs remain backwards-compatible for supported installed native versions; expand/backfill/compare/switch/deprecate migration, with actual rollback/forward-repair rehearsal.

## Database, security and implementation evidence

postgres-schema.sql is a reviewable canonical storage draft, not a production migration ready to run without reconciliation. API shapes, composite tenant keys, actual junction tables for arrays, polymorphic kind resolution, indices and logical unique sources all matter. Generated schema plus JSON validation does not prove RLS/locks. Validate in isolated Postgres, non-owner NOBYPASSRLS runtime roles, authenticated transaction-local tenant context, negative tenant/field tests, concurrent final-unit/slot tests and restore with provider reconciliation before enabling production.

No complete-upfront correctness percentage is assigned. The handoff fixes intended behaviour; actual build evidence, actual provider contracts/approvals and actual company/legal facts are tracked separately. Contract fixtures never fabricate those results.

## Ledger/junction reconciliation

RewardEntry now requires programme_id so changing rule version cannot earn twice for the same source. Reverse uniqueness is original entry + refund/correction origin, allowing legitimate partial refunds while preventing retry duplication. Spend refunds compute cumulative reversed units from original eligible spend and rounding, subtract already reversed units; never reverse more units than originally earned. If a reward already consumed the value, open the reviewed adjustment/recovery case rather than secretly charging money or rewriting history. Programme rule revisions preserve earned promises. Canonical resource/offer/session ID arrays use SQL FK junctions, with API arrays as projections, not two writable sources.
