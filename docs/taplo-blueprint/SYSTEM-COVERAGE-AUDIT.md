## Assessment

The earlier pack established broad product direction; several areas, notably detailed team operations and legal applicability, had much less depth than the feature list suggested. This edition adds concrete contracts and focused research. It still does not prove every atom of the platform is complete. Do not call a domain finished because a heading, schema or diagram exists.

For each domain ask: who acts; on which record/field; under which permission; from which entry point; normal sequence; state/guard; time/money/capacity effect; user-visible wording; recovery; owner/support action; retention/exit; and evidence. Missing one of these is a real gap to resolve, not a styling detail to leave to chance.

## Current evidence levels

Written recommendation; primary-source-supported finding; actual prior site inspection; region schematic; designed reference; typed contract; implementation evidence; provider/device evidence; observed user evidence. These are independent dimensions. This edition adds researched detail and useful artifacts but contains no newly observed real owner/customer sessions and no deployed Taplo implementation.

## Prioritisation by dependency

Identity/access/agreements/data boundaries → offer/capability configuration → inventory/time/capacity commitment → payment/work/customer record → communication/recovery → repeat/rewards/discovery/physical extensions. Design Explore and brand concurrently, but resolve prerequisites before real financial or private-data operations. Run category scenarios across these dependencies rather than researching only one competitor's menu.

## Omission detection

When adding a feature, ask who must set it up, who else is affected, whether it consumes a scarce resource or creates liability, who can change it, what survives cancellation/departure, how it appears in every surface, what gets notified, what can fail, how support sees it and what evidence is required. Team profiles immediately imply invitations, assignment, calendar permissions, owner controls, public links, media rights, commercial seller identity and offboarding. Apply the same reasoning to every feature family.
